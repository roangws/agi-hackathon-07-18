# Cotal Care Deck Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pivot Cotal Command Deck to a hospital command center ("Cotal Care Deck") with a real agent engine: real worker processes, real kill, real anycast task claim, real resume-from-bookmark over an InsForge Postgres durable log, with FHIR-shaped synthetic data.

**Architecture:** A Node parent (`server.js`) spawns 8 worker child processes (`engine/worker.js`), one per clinical agent. Workers claim FHIR-shaped tasks from Postgres via atomic conditional PATCH (PostgREST semantics through the InsForge records REST API), execute steps with real GMI LLM calls, heartbeat every 2s, and durably log every event to `mesh_log`. Killing a worker (SIGKILL) lapses its heartbeat; idle workers take over stale tasks with an atomic conditional PATCH and resume from the bookmark. The existing frontend consumes engine state by polling `mesh_log` + `agent_state` and renders through the existing `say()/log()/setPresence()/pulse()` seams. The current scripted path survives as `?mode=demo`.

**Tech Stack:** Vanilla JS frontend (no build), Node ≥18 (built-in `fetch`) engine, InsForge Postgres + edge functions + Sites, GMI Cloud LLM (via existing `functions/gmi-chat.ts`), RunType (via existing `functions/rt-triage.ts`).

## Global Constraints

- Synthetic data only; no real PHI. Every doc states this.
- Copy must say agents are *operations assist*, not clinical decision-making.
- Keep sponsors visible: Cotal, InsForge, RunType, GMI.
- Zero-dependency rule stays: no npm packages; Node built-ins + fetch only.
- Keys live in `.env` (gitignored); client uses `insforge-config.js` (gitignored, example checked in).
- InsForge records API base: `${IF_HOST}/api/database/records/<table>`, PostgREST-style filters (`?col=eq.val`, `order=`, `limit=`), `Authorization: Bearer <key>`, `Prefer: return=representation` for writes. Inserts take an array.
- Heartbeat interval 2s; stale threshold 6s.
- Frontend modes: `?mode=live` | `?mode=demo`; default = live if `/mesh/status` reachable, else demo + banner.

### Task 3: Worker process (the real agent)

**Files:**
- Create: `engine/worker.js`
- Create: `engine/personas.js` (shared roster: id, name, role, color, persona prompt, channels)
- Create: `engine/test-resume.js`

**Interfaces:**
- `node engine/worker.js <agentId>` runs one agent loop:
  1. Upsert own `agent_state` (status idle, heartbeat now); heartbeat `agent_state` every 2s always; also heartbeat `care_tasks.heartbeat_at` every 2s while owning a task.
  2. Loop: try `claimStale` first (rescue beats new work), else `claimNew`; if none, idle-chatter occasionally (persona line via GMI, logged to a clinical channel) and sleep 3–6s.
  3. On claim: log `task_claimed` (+ note if rescue: `task_rescued`, body includes `resumed from bookmark #N`); set agent_state working with task label.
  4. Read `bookmark`; for step = bookmark+1..steps.length: call GMI via `${IF_HOST}/functions/gmi-chat` with `{system: stepSystemPrompt(persona, task, step), message: stepInput}`; on GMI failure use the step's canned fallback text; `logEvent(kind:'task_step', body: step result, task_id)`; then `patch` task `bookmark=n, artifacts+=result` — bookmark advances ONLY after durable log write succeeds.
  5. Per-step pacing ~3–5s so the demo reads well.
  6. On completion: `patch status=completed`, log `task_completed`, back to idle.
- GMI call budget: step prompts ask for 1–2 sentence clinical-ops artifacts.
- `engine/test-resume.js`: spawn worker A on a fresh task; wait until bookmark ≥2; SIGKILL A; spawn worker B; poll until task completed; assert mesh_log contains exactly one `task_step` per step number (no repeats) and a `task_rescued` event with `bookmark #2`. PASS/FAIL exit.
- [ ] Write `engine/personas.js` with the clinical roster (Atlas charge-nurse orchestrator, Iris triage, Nova pharmacy/med-rec, David discharge coordinator, Sven bed-flow, Echo labs, Vega imaging, Zephyr transport) + persona prompts + per-agent home channels (`#handoffs`, `#pharmacy`, `#bed-flow`, `#rapid-response`).
- [ ] Write `engine/worker.js` per the loop above.
- [ ] Run one worker manually against seeded data; watch mesh_log rows appear.
- [ ] Write + run `engine/test-resume.js` → PASS.
- [ ] Commit: `feat: real agent worker with heartbeat, GMI steps, bookmark resume`

**Interfaces:**
- `MESH=on node server.js` (or `node server.js --mesh`) spawns one child per roster agent via `child_process.fork/spawn('node', ['engine/worker.js', id])`; auto-respawn is OFF for a killed agent until `/mesh/revive` (death must be visible, not auto-healed) but crashed-at-boot workers retry once.
